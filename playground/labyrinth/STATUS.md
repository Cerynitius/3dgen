## 当前配方（全部实测验证，别再回去试旧组合）

**视角 rig（tiles.py）**
- 官方光学：fov 120°、方形 476px（ViT patch14 对齐）、aspect 1.0
- 每机位：平视环 ×4 + 直下 ×1（nadir）+ 凹角相机（两墙夹角各一，俯角 -0.5）
- context 相机：按方位角选 + 可见性优先（bearing picker，对方修复，勿回滚）
- 直视/角落块在方位角循环**外**——在循环内会每机位重复 4 次（血泪教训，见下）

**视图渲染（render.py）**
- 洞穴开凿纹理：低频设计（米级石板/凿痕/沙堆），拒绝 10cm 砖纹
- 低位火盆（0.55m）向上打光，墙面光池贴地线；地面亮漫反射（flat≈1.05）
- 天花板故意暗（0.40）
- 出口 NaN 过滤（nan_to_num）

**前向（recon.py）**
- 输入消毒：nan_to_num。**一个视角的 10 个 NaN 像素曾毒化整个前向**
  （3500 万 means 全 NaN → 对齐 SVD 崩溃 → tile 永远造不出 → 游戏黑洞）

**服务器**
- 环请求按距玩家距离排优先级
- 闲时预烘：队列空时从玩家最后位置向外烘两圈（低优先级，真请求插队）
- 实心 tile（>92% 占据）直接缓存空 tile，不造
- 启动带 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`

**客户端**
- 槽位 splat 场（8M，20 槽 × 400k），cost 驱逐
- 槽位复用时立即滤掉旧索引（等排序回复前不画错深度）——修频闪
- 槽尾惰性 splat 填充（alpha=0, qw=1, scale=1e-4）——零填充会 NaN 黑屏（勿回滚）
- 限速器：前方 tile 未驻留 → 25% 速度
- 加载雾幕（生成时浓、落地缓释）、沙尘微粒、暖黄配色（1.30/1.20/1.02）

## 已枪毙的方向（有数据，别再试）

| 方向 | 结果 |
|------|------|
| 多 worker 并行 | 单调劣化：w1=0.24 t/s → w8=0.13 t/s。GPU 单 build 已饱和 |
| batch=2 前向 | 模型条件路径不认 batch 维（tensor 广播报错），非显存问题 |
| 降分辨率 476→420 | 零收益（3.39s vs 3.33s，噪声内） |
| 提亮重建视图（FILL↑） | 暗角纹理无改善（2-3/10）——不是光暗问题 |
| 全平光 | 更糟（1.5/10）——把 shading 特征也抹了 |
| AO 接触阴影 | 死区带颜色方差 0.12 → 0.077，帮倒忙 |
| 斜俯视角（变体 K） | 死区带原地不动 |
| 两遍制（先扫骨骼再泼） | 三种骨骼呈现形式全败（F 15-27 vs 单遍 34）：模型不认重渲染输入 |

## 病根知识库（今天挖出来的，值钱的）

1. **糊区 = 频率错配**。掠射角/fov 边缘的视图像素先天无高频纹理信号
   （实测能量 0.003 vs 清晰区 0.015）。模型忠实抄空白。修法不是"让它看见"，
   是"纹理频率降到管线载得动的范围"——洞穴纹理就是这么赢的
   （死区带 0.12 → 0.40，四环拉平）
2. **NaN 级联**。渲染 glitch 的个位数 NaN 像素 → 全前向 NaN → 对齐死 →
   tile 黑洞。两道过滤（渲染出口 + infer 前）已上
3. **测量仪器盲区**。bench_surface.true_surface_points 不采样门洞条带——
   接缝缺陷在仪器盲区里活过多轮审计。我的"实心石头当洞报"也是同类错误：
   **任何"洞"的判断先过迷宫占据图**
4. **tile 范围由可见性决定**，不由轴向。24/24 边界与墙体数据吻合：
   内容止于墙面、穿过门洞。±4.35m 裁剪对 4.0m 半间距，两轴对称重叠 0.7m 是设计

## 已知上限

- 单 tile 2.5-4s（32 视角），实时消耗线 0.38 t/s 贴边——预烘 + 限速器兜着
- 显存：49+ 视角时分配器峰值曾到 64GB；现在 ~32 视角 + expandable_segments 稳住
- 纹理"油画感"是 splat 重建的本性，模型不换就这个水准

## 铁律（主人口谕，勿违）

- 骨骼只允许从图片/生成素材中扫描提取，**禁止预制墙形骨骼**

- 验收以游戏实机视觉为准，代理指标（含 bench）都要怀疑一遍
