# Tile 覆盖空洞与重叠：破洞和半透明重影的根因

> 2026-08-20 · 发现：Cherry（实测）+ Kimi Code（前三轮客户端审查）
> 证据级别：全部来自对运行中服务器（192.168.31.172:8092, spec `cefe1f763b5c`）的实测数据
> 相关文件：本目录是客户端；本报告针对的是**服务器侧生成管线**的覆盖几何

## TL;DR

玩家看到的"墙体破洞"和"地面周期性丢失"，以及"半透明重影斑块"，是同一个根因的两个方向：**tile 的内容覆盖范围不等于 tile 间距**。

- x 方向：内容比间距**宽** → 相邻 tile 重叠 ~0.7m → 共享墙被画两遍 → 半透明重影
- z 方向：内容比间距**窄** → 相邻两排之间有 ~1.4m 无人区 → 破洞 / 地面丢失

客户端（截断、四元数、驱逐残尾）全是干扰项。数据从服务器出来就缺条，客户端修不出不存在的内容。

## 实测数据

服务器：seed=1000，spec 关键参数 `cell_m=2.0, span=2, fov_x=1.5, aspect=0.75, view_margin=8, scale_from=perview, unproject=gt`。tile 原点间距 8m。

四块相邻 tile 的内容实际覆盖（世界坐标，米）：

| tile | origin | x 范围 | z 范围 |
|------|--------|--------|--------|
| 0,0  | (5,5)  | 0.65 .. 9.35 | 1.74 .. 8.25 |
| 1,0  | (13,5) | 8.65 .. 17.35 | 1.93 .. 9.35 |
| -1,0 | (-3,5) | -7.35 .. 1.35 | 1.76 .. 9.35 |
| 0,1  | (5,13) | 1.73 .. 8.19 | 9.67 .. 17.35 |

即每块 tile 的内容大约覆盖原点 ±4.35m：

```
x 方向（列间）：  [0,0] ████████░░ overlap ░░████████ [1,0]     ← 重叠 0.7m，双画
                  seam at x=13
                  9.35 ━━ 8.65（重叠带 8.65..9.35 两边都有内容）

z 方向（排间）：  [0,0] ████████░░░ GAP ░░░████████ [0,1]       ← 空洞 1.4m
                  z=8.25 ┄┄ 什么都冇 ┄┄ z=9.67
```

佐证细节：

- tile 0,0 在接缝 x=13 的 ±0.6m 带内 **0 个 splat**；同一地带 tile 1,0 有 28,096 个且分布均匀（10cm bin 直方图平坦）——重叠带内容是双份的。
- tile 0,0 内容 x 止于 9.35（原点后 4.35m），z 止于 8.25（原点后 3.25m）——**x/z 覆盖不对称**，z 向少了整整一米多，这就是死带的来源。
- 数据健康度（排除其他嫌疑）：0 NaN；四元数全部单位范数（采样 20k，wire 序 wxyz 与 /spec 的 layout 声明一致）；缩放全正；alpha 正常；7 块 tile 的 metric_scale 5.1-5.5、align_rmse ~0.1m、floor_err ~±0.03m 全部一致。

## 为什么是"周期性"的

死带出现在**每一排接缝**，不是某一块 tile 的偶发——只要 z 向覆盖（约 6.5m）小于排间距（8m），每 8m 就有一条 1.4m 的洞带。玩家跑图时地面"有时候丢失"就是踩进这条带。

## 修复方向（服务器侧，按改动量排序）

1. **z 向排间距从 8m 缩到 ≤6.5m**（原点加密，以当前实际覆盖为准）——一行参数级改动，立即消灭死带，代价是多 ~23% 的 tile。
2. 或者**扩大重建视野覆盖**让内容够到接缝：看 `view_margin`、`pitch_amp=0.45`、`aspect=0.75`、视图排布（n_az/n_pos）这几个参数为什么 x/z 覆盖不对称。
3. x 向重叠带的客户端去重（相邻 tile 同墙双画）：客户端没有跨槽去重，要么服务器侧合并边界墙，要么客户端按重叠带裁一边。注意这会让重影和破洞此消彼长，先补洞再谈去重。

## 复现方法

# 复核与修复（2026-08-20）

复核方式：对运行中的 server 重测。**测量全部复现**，但机制不是报告说的那样；真正的根因在别处，
而且修起来是免费的（视图数不变），不需要方案 1 的加密原点（+23% tile）。

## 一、测量复现，但结论不成立

报告采样的四块 tile 确实是 x 宽 z 窄。多取几块就不成立了：

| tile | dx | dz | | tile | dx | dz |
|------|------|------|---|------|------|------|
| 0,0 | 8.66 | 6.41 | | **0,1** | **6.43** | **7.65** |
| 1,0 | 8.69 | 7.38 | | **1,1** | **7.43** | **8.68** |

(0,1) 是 x 窄，(1,1) 是 z 宽。**覆盖范围不是轴的性质，是可见性的性质**：把 6 块 tile 的
24 条边界逐条对墙位——**24/24 完全相关**：边界上只要有一个门洞，内容就穿过去；边界全封死，
内容就停在墙面上。相机看不穿墙，如此而已。

裁剪本身是**对称**的：`crop_to_footprint` 保留原点 ±4.35 m，而 tile 间距的一半是 4.0 m，
所以**两个轴都是设计上重叠 0.7 m**，z 方向不存在设计上的空洞。

## 二、被当成空洞的那 1.4 m，是实心墙的内部

z=8.25..9.67 这条带落在 grid z∈[8,10] 的墙板里。墙板两个**面**（z=8 和 z=10）分别被两块
tile 覆盖到，中间那段是墙心，玩家永远看不到。

用**含门洞**的地面真值重测（`bench_surface.true_surface_points` 只采 cell 内部、
从不采门洞条带——恰好是接缝所在，所以原来的审计看不到这里）：接缝带 `|x-9|<0.35` 的
真实表面 **93.8% 在 5 cm 内**，是全世界覆盖最好的地方，不是洞。

另：报告称「接缝 x=13」——x=13 是 tile (1,0) 的**原点/中心**，不是接缝；真正的接缝在 x=9。
而且引用的数据（tile 0,0 在那里 0 个 splat、tile 1,0 有 28,096 个）说明的是**只有一块 tile
有内容**，正好与「双画」相反。

## 三、重叠是真的，但无害

x 接缝重叠带内 31.9% 的表面确实由两块 tile 同时画。但两份重建**相距中位数 2.5 cm
（p90 5.3 cm）**，而体素剪枝后的 splat 间距本身就是 ~4 cm——两份重合在一起，不构成错位重影。
而且双重覆盖只会让表面**更不透明**，不会更透明。

## 四、真正的问题：z 接缝的覆盖质量确实比 x 差——但原因是相机排布

| | 中位距 | <5cm | >25cm |
|---|---|---|---|
| x 接缝 | 1.4–1.8 cm | 93.8% | 0–5% |
| **z 接缝** | 2.4–3.8 cm | **56.9%** | **13.4%** |

根因在 `tiles.py:render_rig` 的 **context 相机选点**：ring 按行主序构造，然后用
`np.linspace` 在**列表下标**上均匀取点——下标均匀 ≠ 方向均匀。span=2 / n_context=4 时它恒定
选中 `(-1,-1)、(-1,0)、(2,1)、(2,2)`：西、东两个边中格加两个对角，**从来不选正北或正南**。
正对 z 接缝的那四格 `(0,-1)、(1,-1)、(0,2)、(1,2)` 在这条规则下不可达。

tile 的边界带几乎全靠正对它的那台 context 相机重建，所以 x 接缝有、z 接缝没有。

**修法**：按**方位角**均匀选，并在同一方位的候选里优先选**能看进 tile** 的格子（正对方向的
墙是开的）。相机数不变，成本不变。

## 五、结果（12 块 tile 的逐块审计 + 接缝带实测）

| | 原 linspace | 仅按方位 | **方位+可见性（已采用）** |
|---|---|---|---|
| F@5cm | 39.5% | 40.9% | **43.0%** |
| 最差 tile | 31.3% | 27.7% | **35.4%** |
| 精度中位 | 26.1 cm | 21.1 cm | **18.3 cm** |
| 覆盖 <5cm | 55.4% | 58.9% | **63.8%** |

接缝带（对玩家实际驻留的 3×3 并集测）：

| | 修复前 | 修复后 |
|---|---|---|
| z 接缝 <5cm | 56.9% | **84.3%** |
| z 接缝 >25cm | 13.4% | **3.5%** |
| x 接缝 <5cm | 93.8% | 96.3% |
| tile 内部 <5cm | 66.8% | **79.7%** |
| tile 内部 >25cm | 11.3% | **6.6%** |

速度不变：实测行走 63 m / 45.2 s，**0 次踩空**，维持 1.40 m/s。世界版本
`b3182eacd9cb → f78b33bf16a3`。

## 六、仍然存在的

tile 内部仍有 6.6% 的表面离最近 splat 超过 25 cm，精度中位 18.3 cm——这是当前视图数下模型的
上限（952px 已验证无改善），不是排布问题。方案 3（重叠带去重）依旧不建议做：重叠是接缝覆盖
最好的原因，去掉它就是把洞换回来。
